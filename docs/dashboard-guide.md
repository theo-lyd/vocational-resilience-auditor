# Dashboard Guide: Vocational Resilience Auditor

Audience: policy analysts, operations teams, and engineering contributors.

Goal: explain how to use the dashboard, how to interpret each metric and feature, and how the dashboard answers core business questions.

---

## 1. What This Dashboard Is For

The dashboard translates model outputs into decision-ready insight about district-level workforce resilience.

Primary use cases:
- Identify where workforce supply is most constrained.
- Understand severity and uncertainty before acting.
- Review model quality evidence.
- Generate district-level policy recommendations with caveats.
- Monitor run health and data quality signals.

---

## 2. How to Launch

From repository root:

```bash
streamlit run app.py
```

Then open the URL shown by Streamlit (typically `http://localhost:8501`).

If no data appears, run pipeline first:

```bash
python scripts/run_pipeline.py
```

## 4. Core Business Questions and Where to Answer Them

1. Which districts are most at risk right now?
- Use: `Executive` tab + `Risk Diagnostics` tab.
- Signals: `Systemic Risk` count, risk-exposed share, demand-gap leaderboard.

2. How severe is the supply-demand imbalance?
- Use: `Risk Diagnostics` tab.
- Signals: supply-vs-demand scatter, `demand_gap`, `resilience_score`.

3. How much confidence should we have in district results?
- Use: `Risk Diagnostics` + `Model Diagnostics`.
- Signals: `confidence_score`, `sensitivity_impact`, outlier share, MAE by model.

4. What policy action is suggested for a specific district?
- Use: `Policy Drilldown` tab.
- Signals: generated recommendation + methodology notes + caveats.

5. Is the system operationally healthy enough for policy use?
- Use: `Operations` tab.
- Signals: run success trend, quality/SLA failures, what changed since last run.

## 5. Tab-by-Tab Guide

## 5.1 Executive

Purpose:
- Fast leadership-level narrative and headline KPIs.

What you see:
- Total districts.
- Count in each risk band.
- Risk-exposed share (Systemic Risk + Watch).
- Median resilience score and score IQR.
- Risk distribution chart.
- Auto-generated `Top 5 Critical Findings`.

How to interpret:
- High risk-exposed share means broad structural pressure.
- Median score below 1.0 indicates system-wide undersupply pressure.
- Wider IQR indicates uneven regional conditions and priority segmentation need.

---

## 5.2 Risk Diagnostics

Purpose:
- Explain why districts are risky and where gaps are largest.

What you see:
- Supply-vs-demand scatter with parity line.
- Demand-gap leaderboard.
- Confidence/sensitivity/outlier summary by risk band.

How to interpret:
- Points below parity line indicate projected supply below demand proxy.
- Larger positive `demand_gap` means larger shortfall pressure.
- High outlier share suggests results need additional contextual caution.

---

## 5.3 Model Diagnostics

Purpose:
- Evaluate forecast quality and model reliability.

What you see:
- Model MAE comparison chart.
- Backtest summary table (MAE, median error, p90 error, districts evaluated).
- Risk-band structural summary.

How to interpret:
- Lower MAE is better.
- High p90 error indicates tail-risk in model performance for some districts.
- Compare model quality with policy sensitivity before committing high-cost interventions.

---

## 5.4 Policy Drilldown

Purpose:
- Translate analytics into district-specific recommendations.

What you see:
- District selector.
- District headline metrics (risk band, score, graduates, beds).
- Recommendation text from policy engine.
- Methodology notes.

How to interpret:
- Treat recommendation as evidence-guided draft.
- Always read caveats and methodology notes before deciding implementation scope.

---

## 5.5 Operations

Purpose:
- Verify analytical outputs are operationally trustworthy.

What you see:
- Recent pipeline runs and success-rate indicator.
- Quality/SLA outcomes by severity.
- Auto-generated `What Changed Since Last Run` notes.

How to interpret:
- Frequent failed checks or unstable run status reduces confidence for policy decisions.
- Use run-over-run notes to quickly detect regressions in performance or quality.

---

## 5.6 Data Explorer

Purpose:
- Deep filter/sort/export interface for analysts.

What you see:
- Filters by risk band and selected model.
- Full district table with confidence/sensitivity, gap, and ratio fields.
- CSV download button.

How to interpret:
- Use this view for ad-hoc investigation and stakeholder-specific extracts.

## 6. Metric and Feature Dictionary

`risk_band`
- Classification of district resilience condition.
- Values: `Systemic Risk`, `Watch`, `Resilient`, `Missing demand baseline`.

`resilience_score`
- Core ratio proxying supply-vs-demand resilience.
- Formula:

$$
\text{resilience\_score} = \frac{\text{forecasted\_graduates}}{\text{total\_beds}}
$$

Interpretation:
- `< 1.0`: projected undersupply pressure.
- `1.0 to < 2.0`: moderate watch zone.
- `>= 2.0`: comparatively resilient.

`forecasted_graduates`
- Forecasted district vocational graduate supply at selected horizon.

`total_beds`
- Demand proxy from hospital capacity dataset.

`coverage_ratio`
- Equivalent practical interpretation to resilience ratio under valid demand baseline.

`demand_gap`
- Computed as `total_beds - forecasted_graduates`.
- Higher positive value indicates larger projected shortfall.

`confidence_score`
- Methodology-derived confidence indicator for district interpretation.

`sensitivity_impact`
- Indicates how strongly score interpretation may shift under methodological perturbations.

`outlier_flag`
- Marks districts with atypical distributional behavior requiring caution.

`Top 5 Critical Findings`
- Auto-generated executive narrative synthesized from current run data.

`What Changed Since Last Run`
- Auto-generated operational narrative comparing latest vs previous run and quality-check trends.

## 7. Decision Workflow (Recommended)

1. Start in `Executive` for system-level posture.
2. Use `Risk Diagnostics` to shortlist high-priority districts.
3. Check `Model Diagnostics` to assess reliability before intervention planning.
4. Move to `Policy Drilldown` for district-specific recommendation drafts.
5. Confirm run/data health in `Operations` before publishing outcomes.
6. Export scoped subsets via `Data Explorer` for stakeholder distribution.

---

## 8. Common Interpretation Mistakes to Avoid

1. Treating one metric in isolation.
- Always combine risk band + confidence + sensitivity + outlier context.

2. Assuming model quality is uniform across all districts.
- Review tail error metrics and district-level caveats.

3. Ignoring operational health checks.
- Policy decisions should not rely on stale/unstable runs.

4. Reading `Missing demand baseline` as low risk.
- It means insufficient denominator context, not safety.

---

## 9. What This Dashboard Does Not Yet Cover

1. Geographic choropleth maps (requires geospatial boundary integration).
2. Exogenous shock modeling (policy shocks/macroeconomic changes).
3. Full causal inference (current output is diagnostic + forecasting-driven support).
